# LD Toy Pad — macOS и Windows

Самостоятельное приложение на основе каталога LD-ToyPad-Emulator. Node.js, браузер и Linux-виртуалка для запуска готового приложения не нужны.

**Это экспериментальный клиент для Toypad Listener v2. Обычные сборки Cemu/RPCS3 не принимают его команды.** Игра, эмулятор и игровые файлы не входят в приложение. Работа с настоящей консолью не поддерживается.

## Что работает в приложении

- Каталог персонажей и транспорта из исходного проекта, поиск по имени, миру и способностям.
- Создание независимых фигурок с уникальным UID, импорт и экспорт 180-байтовых `.bin`.
- Семь мест на паде: разместить, убрать, переместить.
- Локальное соединение с Cemu/RPCS3 через Toypad Listener v2, порт по умолчанию `9191`.
- Постоянные файлы фигурок: совместимый эмулятор может записывать в них улучшения транспорта.
- Каталог и создание файлов работают без запущенной игры.

В каталоге сохранены данные оригинала, включая неизвестные/невыпущенные варианты. Наличие записи не означает, что её поддерживает конкретная версия игры. Новые транспортные теги создаются без улучшений.

## Запуск

### macOS

Распакуйте архив для своего процессора и откройте `LD Toy Pad.app`. `arm64` предназначен для Apple Silicon (M1 и новее), `x64` — для Intel. Приложение можно перенести в Applications.

Сборка не имеет подписи Developer ID и нотариализации Apple. Если macOS блокирует запуск скачанной сборки, используйте системное разрешение в **System Settings → Privacy & Security → Open Anyway**, только если доверяете источнику. Отключать Gatekeeper не нужно.

**Приложение для macOS и совместимый эмулятор — разные сборки.** Готовый macOS-эмулятор с Toypad Listener здесь не прилагается. В проверенных релизах указанных ниже форков подтверждены Windows-сборки; macOS-версию эмулятора понадобится собрать отдельно. Нативность `.app` не означает автоматической совместимости с обычным Cemu/RPCS3.

### Windows

Распакуйте **всю папку** из Windows-архива и запустите `LD Toy Pad.exe`. DLL и папки рядом с `.exe` необходимы; перенос одного `.exe` не работает. Это portable-сборка, без установщика. Она не подписана коммерческим сертификатом. Windows-сборка собрана на macOS, запуск на Windows ещё не проверен.

## Подключение к игре

1. Установите эмулятор с актуальным Toypad Listener v2:
   - [Cemu Remote Toypad](https://github.com/harrysof/Cemu-2.6-Remote-Toypad-Build)
   - [RPCS3 Seamless Toypad](https://github.com/NeverCookFirst/RPCS3-Seamless-Toypad-Build)
2. В Cemu откройте **Tools → Emulated USB Devices** и включите Dimensions Toypad. В RPCS3 виртуальный пад создаётся при запуске игры. Отключите физический пад, если он имеет приоритет над виртуальным.
3. Запустите LEGO Dimensions в эмуляторе **на том же компьютере**.
4. В LD Toy Pad оставьте порт `9191` (или задайте одинаковый порт в обоих приложениях) и подключитесь.
5. Выберите фигурку из библиотеки, затем свободное место на паде. Результат проверьте в игре.
6. Перед завершением уберите фигурки с пада, чтобы эмулятор закрыл файлы и сохранил изменения. После этого закройте игру и приложение.

Приложение проверяет ответ LED v2 до отправки фигурок. «Подключено» означает ответ совместимого listener. «Команда отправлена» означает передачу команды; протокол не подтверждает появление персонажа в игре.

Управляйте падом из одного приложения. Listener не позволяет запросить список занятых мест. После перезапуска приложения или обрыва связи отображаемые места сбрасываются; фигуры в игре могут остаться. Удалите их через приложение/встроенный пад эмулятора или перезапустите игру. Не меняйте позиции параллельно через встроенное окно эмулятора.

### Если используется обычный Cemu

В Cemu 2.4+ есть встроенный виртуальный пад. Можно создать фигурку в этом приложении, экспортировать `.bin`, затем загрузить файл через **Tools → Emulated USB Devices** в Cemu. Это ручной обмен файлами: кнопки размещения в LD Toy Pad не управляют обычной сборкой Cemu. [Официальная инструкция](https://wiki.cemu.info/wiki/LEGO_Dimensions).

## Библиотека и улучшения

Кнопка открытия папки данных показывает библиотеку. Обычно она находится:

- macOS: `~/Library/Application Support/LD Toy Pad/`
- Windows: `%APPDATA%/LD Toy Pad/`

`library.json` содержит список фигурок, `tags/*.bin` — их данные. Приложение передаёт эмулятору путь к рабочей копии тега; оригинал импортированного файла не меняется. Повторная загрузка всегда читает файл с диска, сохраняя улучшения, которые записал эмулятор. После перестройки транспорта имя обновляется при снятии или следующем чтении фигурки.

Сделайте копию всей папки данных при закрытой игре. Не редактируйте и не переносите рабочие теги, пока эмулятор их использует. Один UID нельзя загрузить одновременно в несколько мест; для второго экземпляра создайте новую фигурку в каталоге.

## Сборка из исходников

Требуется Node.js 22.12+ (для разработки; для готового приложения не нужен).

```sh
cd desktop
npm ci
npm test
npm start
npm run build:mac
npm run build:mac:intel
npm run build:win
```

Результаты находятся в `desktop/dist/`. Для сборки macOS нужен macOS. Windows portable-папка может собираться на macOS без Wine. Скрипт копирует актуальный каталог из `../server/json` перед упаковкой. Исходная Linux-версия проекта продолжает запускаться через корневой `npm start`.

GitHub Actions workflow `desktop.yml` собирает macOS arm64/x64 и Windows x64 по ручному запуску или изменению файлов desktop/каталога. Результат — артефакты workflow, не опубликованный релиз. Для публичного распространения можно отдельно настроить подпись и нотариализацию.

## Проверка и ограничения

Автотесты проверяют криптографические векторы фигурок, формат TCP-команд, совместимость фрагментированных ответов, отказы подключения и сохранение данных библиотеки. Проверка связи использует тестовый TCP-сервер. Приложение не включает тестовые соединения в штатном режиме.

**Полноценный игровой тест пока не проведён:** у пользователя нет установленного эмулятора/игры. Поддержка протокола подтверждена исходниками, а не прохождением игры. macOS-сборка эмулятора с listener отдельно не собиралась.
